Add Pi-compatible machine-readable batch output on the same prompt execution path as text print mode.

Dependencies:

- Depends on `TODO-e1696402`; do not create a second prompt loop.

Contract and behavior:

- Extend the concrete print-mode options with `output: "text" | "json"` (or Pi-compatible equivalent).
- Subscribe before the first prompt and unsubscribe in every completion/failure path.
- Emit the current session header as the first JSONL record when available, followed by every admitted `AgentSessionEvent` in source order.
- Use strict one-record-per-LF JSONL framing. Preserve Unicode; reject or contain values that cannot be serialized.
- Keep stdout-domain records free of ANSI, diagnostics, startup chatter, stack traces, credentials, runtime API keys, and browser/auth secret input.
- Route diagnostics/errors through the result/error boundary, not into the JSONL stream. Define behavior when serialization or output fails mid-run.
- Bound individual record bytes and outstanding writer work. Respect backpressure or fail/abort deterministically rather than retaining an unbounded event queue.
- JSON mode must use the exact same `AgentSession` prompt/tool/persistence/cancellation behavior as text mode.
- Export the JSONL record/serializer types only if they form a concrete supported process contract; do not introduce a universal projection schema or RPC envelope.

Acceptance tests:

- Header is first, then agent/session events in exact subscription order, each ending in one LF.
- Streaming text/thinking/tool lifecycle events are represented without modification or reordering.
- Multi-prompt invocation stays one continuous ordered stream.
- Unicode line/paragraph separators remain valid JSON text and do not create extra JSONL records.
- Every line parses independently with `JSON.parse`.
- Provider errors produce their normal events and a non-success mode result without contaminating stdout.
- Oversized/unserializable records and slow writers hit explicit bounds and release the subscription.
- No secret from auth storage, `--api-key`, or hidden composer input appears in records.
- Text mode behavior remains unchanged.

## Implemented

- Extended the existing `runPrintMode()` execution path with `output: "json"`; prompt sequencing and result classification remain shared with text mode.
- JSON mode flushes the session header first, subscribes before prompting, emits source-ordered `AgentSessionEvent` records, and always unsubscribes before return.
- Added strict LF framing with record, pending-record, and pending-byte bounds plus one sequential writer drain.
- Writer, serialization, and pending-queue failures abort active work without disposing the caller-owned session and return closed output errors.
- Added coverage for header/event order, multi-prompt continuity, Unicode separators, independent line parsing, provider errors, runtime/stored-secret exclusion, slow writers, unserializable tool events, and subscription release.
- Updated SDK, architecture, and parity documentation; RPC remains deferred.
