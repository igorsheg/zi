Prepare `@zi/coding-agent` to be a supported in-process building block before adding more application modes.

Owner and contract:

- Make the high-level runtime result explicit (`AgentRuntime` or equivalent) instead of relying on the inferred return type of `createAgentRuntime()`.
- Document and test lifetime ownership: the creator owns `AgentSession.dispose()`; print/JSON/TUI modes may subscribe, prompt, abort, and settle but never dispose a caller-owned session.
- Clarify the public distinction between high-level cwd/path/service assembly and the lower-level `createAgentSession({ services, ... })` function. Rename or narrow exports only if that makes the two construction levels unambiguous; do not add a universal mode facade.
- Keep `ZiPaths`, `SettingsManager`, `FileCredentialStore`, `ModelRegistry`, `ResourceLoader`, and `SessionManager` instance-scoped. Preserve the one credential store and explicit selected/unselected model state.
- Give exported runtime/service/options/result types stable readonly surfaces. Do not expose writable atoms, raw agent mutation, hidden globals, or a generic service locator.
- Keep the test-only raw `Models` adapter under `@zi/coding-agent/testing`.
- Add concise SDK documentation/examples for minimal in-memory use, persistent cwd-bound use, custom models, and caller-owned disposal.

Acceptance tests:

- A consumer can create, subscribe to, prompt, wait for, abort, and dispose a session without importing CLI or TUI packages.
- Two runtimes in one process retain independent cwd, settings, credentials, sessions, cancellation, and model state.
- A caller-supplied in-memory session remains non-persistent and does not inspect `$HOME` after its owners are provided.
- A mode can return while the session remains usable; only creator disposal closes it.
- Public package exports typecheck from a small external-consumer fixture.

Pi-mono references at pinned commit `0e6909f0` (`v0.80.6`):

- `packages/coding-agent/src/core/sdk.ts`: `CreateAgentSessionOptions`, `CreateAgentSessionResult`, high-level `createAgentSession()`, dependency injection, and public re-exports.
- `packages/coding-agent/src/core/agent-session-services.ts`: service assembly boundaries.
- `packages/coding-agent/src/core/agent-session-runtime.ts`: runtime/session rebinding and lifetime separation; port only capabilities required by current Zi modes, not the whole host.
- `packages/coding-agent/src/index.ts`: supported SDK surface.
- `packages/coding-agent/examples/sdk/01-minimal.ts`, `02-custom-model.ts`, `05-tools.ts`, `09-api-keys-and-oauth.ts`, `10-settings.ts`, `11-sessions.ts`, `12-full-control.ts`, and `13-session-runtime.ts`: consumer use cases and ownership expectations.
- Relevant SDK tests: `test/sdk-session-manager.test.ts`, `test/sdk-stream-options.test.ts`, `test/sdk-skills.test.ts`, and `test/agent-session-dynamic-provider.test.ts`.

Do not copy Pi's extension/runtime breadth yet. This todo establishes a narrow stable spine for the capabilities Zi already owns.

## Implemented

- Added explicit public `AgentRuntime` and `AgentRuntimeServices` contracts with readonly options/service fields and frozen runtime/service shells.
- Documented the high-level `createAgentRuntime()` versus caller-assembled `createAgentSession()` boundary and creator-owned disposal.
- Kept raw `Models` injection in the testing subpath and made its options readonly.
- Added SDK acceptance coverage for prompting/subscription/wait/abort/disposal, mode-like caller reuse, low-level in-memory assembly, two-runtime isolation, and package-name import typechecking.
- Added README SDK examples for persistent, non-persistent, credential-aware custom-model, and low-level service-owned use.

Verification: `bun run check` passes (80 coding-agent tests, 88 TUI tests, 2 CLI tests).
