Implemented and tightened the below-composer picker stack.

Owners and API:

- `Composer` remains the sole native textarea and focus owner.
- `PickerStack` owns a non-empty open-frame tuple, selected row per frame, suspended parent filters, top-frame fuzzy filtering, push/pop, replacement, and disposal. Active filter text is passed from the composer and never retained as mirrored input state.
- `PickerStackView` renders only the public top-frame projection below the composer and contains no TextareaRenderable.
- `PromptStore` owns typed command/model workflows and revisioned one-shot composer edit requests. It provides rows and interprets selected IDs without moving domain actions into the mechanical stack.

Behavior:

- Tab completion now retains focus and moves the native cursor to the end of `/model `.
- `/model` keeps the original composer mounted and focused while model rows appear beneath it.
- Composer text filters, navigates, and selects the active model frame.
- Selecting a slash command pushes a child frame; Escape pops it, restores the parent filter and cursor, then closes the parent on the next Escape.
- Picker-active Return, Tab, and vertical navigation cannot fall through to multiline editing, queue restoration, or prompt submission.
- Model success/failure/cancel clears or restores the composer through explicit edit requests.
- Async cancellation and session replacement retain stale-completion rejection.

Invariants:

- depth is bounded to 8 frames, each frame to 2048 rows, and each suspended filter to 8192 characters;
- row IDs are unique and configured selection must identify an admitted row;
- forbidden replacement on a closed stack throws;
- public presentation strips internal selection indices and suspended filters.

Removed `ModelSelectorView` and its second textarea. Added pure nested/bounds/forbidden-transition tests plus real OpenTUI focus/filter/cursor/key-capture/push-pop coverage. Added ADR 0008 and updated AGENTS, terminology, architecture, TUI architecture, ADRs 0005/0006, and the parity roadmap.
