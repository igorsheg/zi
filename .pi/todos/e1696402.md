Implement the first non-interactive application mode as a concrete one-shot owner over an existing `AgentSession`.

Dependencies:

- Start after `TODO-602530f5` stabilizes the SDK/runtime construction and lifetime contract.

Behavior and ownership:

- Add a coding-agent-owned `runPrintMode()` (or equivalently concrete name) that receives an existing session, an ordered non-empty prompt list, and a narrow output boundary.
- The mode subscribes/prompts/waits but never creates or disposes the session. The caller remains responsible for final abort/disposal.
- Send prompts sequentially through `AgentSession.prompt()`; do not bypass queue, persistence, tool, provider, or cancellation policy.
- Text output emits only text blocks from the final assistant message after the final prompt. Thinking, tool events, and intermediate assistant turns stay off stdout.
- Return a concrete result/exit status distinguishing success, provider error, abort, missing model, and output failure without leaking credentials.
- Reject an unselected session before prompting with the same actionable `/login`/model guidance expressed appropriately for a headless caller.
- Keep process globals out of this owner: no `process.exit`, signal registration, terminal detection, console calls, or direct stdout/stderr. CLI process composition comes later.
- Bound prompt count/bytes and output writes. A slow or failed writer must not create an unbounded retained queue.
- Preserve caller reuse: after a successful or failed print invocation settles, a non-disposed session remains in a defined state.

Acceptance tests with real `AgentSession` and faux providers:

- One prompt prints only final assistant text and preserves the session journal.
- Multiple prompts run sequentially and print only the last response.
- Tool execution still runs through the normal loop but tool/thinking/intermediate output is absent from text output.
- Assistant `error` and `aborted` stop reasons produce non-success results and stderr-domain messages.
- Missing model is rejected before provider work.
- Cancellation settles subprocess/provider work without disposing the session.
- Output failure is bounded, propagated, and leaves no active subscription.
- The same session can be prompted again by its caller after mode return when its state permits.

Pi-mono references at pinned commit `0e6909f0` (`v0.80.6`):

- `packages/coding-agent/src/main.ts` around `runPrintMode(...)`: CLI-to-mode composition only, not business logic.

Do not add JSON, stdin parsing, TTY detection, or RPC commands in this todo. Establish the text semantics and reusable ownership first.

## Implemented

- Added coding-agent-owned `runPrintMode(session, options)` over a caller-owned `AgentSession` with no process, signal, terminal, or disposal ownership.
- Added closed success, provider-error, abort, missing-model, invalid-input, and output-error results.
- Bounded prompt count/UTF-8 bytes and final text chunk/byte output; writer calls are awaited sequentially for backpressure.
- Text output emits only text blocks from the final assistant message after ordered prompts.
- Added real-session/faux-provider coverage for tools, thinking omission, multi-prompt ordering, journal preservation, cancellation, session reuse, model/provider/admission failures, writer failure, and all bounds.
- Exported the mode through `@with-zi/coding-agent` and documented SDK/application-mode ownership.
