Implement the supported subset of Pi's `/settings` UX only after queue-mode session mutations are authoritative.

Dependencies:

- Depends on `TODO-2842407f`.
- Reuse the stable SDK/session surface from `TODO-602530f5`; do not let the TUI write `SettingsManager` directly for live session behavior.

Scope and ownership:

- Add the coding-agent built-in `/settings` descriptor and a closed `InteractiveCommand` intent.
- `PromptStore` owns the settings workflow and operation identity; `PickerStack` owns nested scope/setting/value mechanics; `PromptView` remains native input/key presentation only.
- Support only settings OpenZi currently owns and can apply coherently: thinking level, steering mode, and follow-up mode. Model remains `/model`; do not predeclare Pi settings for compaction, themes, images, extensions, trust, transport, or telemetry.
- Represent settings workflow as explicit states such as choosing scope, choosing setting, and choosing value. Keep one prompt workflow source of truth.
- Make global/project scope explicit because OpenZi layers defaults < global < project < runtime. Do not silently guess which file the user meant. Show effective value and whether a project value shadows global state.
- All live-affecting selections call `AgentSession` mutations. Never update settings files and agent fields separately from TUI code.
- Bring thinking-level persistence into the same coherent scoped/effective transition rule if the queue-mode todo exposes a mismatch in the existing `setThinkingLevel()` behavior. Invalid project/global settings must refuse writes and surface their scoped diagnostic.
- Reuse the composer-owned picker stack: `/settings` opens scope/settings rows; selecting a setting pushes its values; Escape restores the suspended parent filter; the composer remains mounted/focused.
- Rows and hints derive from concrete descriptors colocated with the owning domain, not hard-coded across view components. Do not create a generic settings registry until additional packages need one.
- Session replacement, Escape, and disposal reject stale selection completion. No event bus.

Initial supported rows:

- Thinking level: values from `session.getSupportedThinkingLevels()`, current effective value marked.
- Steering mode: `one-at-a-time` and `all`, current live/effective value marked.
- Follow-up mode: `one-at-a-time` and `all`, current live/effective value marked.

Acceptance tests through real OpenTUI:

- Slash completion and `/settings` invocation open the picker without replacing the composer input.
- Global/project scope is explicit and inherited/shadowed values are represented accurately.
- Nested value selection and Escape restore parent filters exactly.
- Thinking selection clamps only through `AgentSession`; unsupported values never appear.
- Steering/follow-up selections persist the requested scope and immediately affect live queue delivery.
- A project override remains effective after editing global settings and the UI explains the shadowing rather than claiming a false live change.
- Invalid/oversized settings files surface errors without overwrite.
- Selection failure, session replacement, and disposal cannot apply stale values.
- Existing `/model`, `/login`, `/logout`, queue, selection-copy, and exit precedence remain unchanged.

Do not add RPC mode, a generic settings/plugin registry, or frontend-owned settings state.

## Implemented

- Added the coding-agent `/settings` descriptor and closed terminal command intent.
- Added explicit `choosing_settings_scope | choosing_setting | choosing_setting_value` PromptStore states with a session-bound operation owner.
- Added composer-owned global/project, setting, and value frames for thinking, steering, and follow-up modes, including inherited/saved/effective metadata and project-shadow hints.
- Routed every mutation through `AgentSession`; thinking mutation now uses the same scoped requested/effective contract, model clamp, invalid-input validation, and effective-only event semantics as queue settings.
- Added nested Escape/filter restoration, shadowed-global feedback, invalid-file refusal, supported-thinking filtering, and stale session-replacement coverage through unit and real OpenTUI tests.
- Updated README, architecture, and parity evidence; no settings registry, event bus, RPC, or frontend-owned durable state was introduced.

Verification: `bun run check` passes (103 coding-agent tests, 95 TUI tests, 16 CLI tests).
