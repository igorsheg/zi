# extension v2 conformance matrix

## status

contract for `zi-fex.11`.

short answer:

- yes for product-surface capability parity. zi v2 can claim pi-mono-level extension capability when the comparison is "what product seam can an extension reach?" rather than "does lua receive the same raw host object graph?" (`docs/extensions.md:18-28`; `docs/adr/extensions-v2-cutover.md:25-34`)
- no for raw reach-through parity. v2 explicitly rejects direct tui → lua reach-through, mailbox/snapshot leakage, and other ownership exceptions. (`docs/extensions.md:13-16`; `docs/runtime.md:16-19`)
- subagent/job observer classes are now closed at the contract layer: `job_*` and `subagent_*` are observe-only events over committed retained state, not raw child transport. (`docs/extensions-events.md:93-143`; `docs/extensions-jobs-subagents.md:267-290`)

## doctrine

this matrix judges parity the way the root adr does: preserve or expand pi-mono-level capability, but only through one truthful v2 api that fits agent-owned extension execution, host-owned boundaries, and no compatibility theater. (`docs/adr/extensions-v2-cutover.md:25-34,37-43,60-77`)

## status taxonomy

| status | meaning |
| --- | --- |
| direct equivalent | same capability class, materially same observable outcome. (`docs/extensions-ui-contract.md:68-69`) |
| host-owned reinterpretation | same product capability, but the object crossing the boundary is a host-owned primitive / retained record instead of a borrowed pi-mono object or callback graph. (`docs/extensions-ui-contract.md:68-70`; `docs/runtime.md:16-19`) |
| deliberate divergence | parity is kept or expanded, but the public abstraction changes on purpose to fit runtime roots, rebinding, or ownership doctrine. (`docs/adr/extensions-v2-cutover.md:30-34,60-77`; `docs/extensions-events.md:20-21,259-268`) |
| excluded | zi does not expose that pi-mono seam across the public boundary. (`docs/extensions-ui-contract.md:70-70,90-92`) |
| open | the v2 docs claim the capability class, but another current v2 contract still leaves the public semantics incomplete. |

## representative scenarios

1. **override builtin `read`, keep builtin rendering.** a higher-precedence root wins the `read` tool definition, while builtin-family inheritance keeps `call` and/or `result` presentation if the new semantic shape still fits. (`docs/runtime-roots.md:138-147`; `docs/extensions-tools.md:312-345,391-406`)
2. **keep colliding slash commands callable.** two extensions can both register `review`; the host resolves `review:1` and `review:2` instead of silently hiding the loser. (`docs/runtime-roots.md:133-146`; `docs/extensions-commands-flags-actions.md:146-159`; `.references/pi-mono/packages/coding-agent/src/core/extensions/runner.ts:474-520`)
3. **rebind by state, not pointer.** `/reload`, `/new`, `/resume`, and `/fork` kill old live handles, rebuild discovery, bind a fresh generation, and republish lifecycle edges with fresh binding ids. (`docs/extensions-events.md:191-223`; `docs/extensions-state-rebinding.md:190-317,351-409`)
4. **rewrite the next provider call in stages.** surviving prompt text goes through `input`, system-prompt/message injection goes through `before_agent_start`, message-list rewriting goes through `context`, and provider payload rewriting goes through `before_provider_request`. (`docs/extensions-commands-flags-actions.md:60-67`; `docs/extensions-events.md:128-137,228-237`; `.references/pi-mono/packages/coding-agent/src/core/extensions/runner.ts:714-835`)
5. **register a provider before bind, mutate it after bind.** load-time provider claims queue until bind, then the same register/unregister contract stays live without a forced reload. (`docs/extensions-providers.md:13-16,27-62,75-84`; `.references/pi-mono/packages/coding-agent/src/core/extensions/runner.ts:278-312`)
6. **ask for ui without borrowing tui internals.** prompts, status, title, widgets, panels, overlays, and transcript presentation stay possible, but only through host-owned leases / records / renderer refs, not raw component factories or terminal input listeners. (`docs/extensions-ui-contract.md:72-92,153-180,198-307`; `.references/pi-mono/packages/coding-agent/src/core/extensions/types.ts:121-123,133-223`)
7. **attach durable metadata to session entries.** a semantic `message` observer sees `message.entry_id`, attaches notes and labels through `ctx.session`, and later commands query `ctx.session.entries({ label = "decision" })` without reading jsonl or transcript render rows. (`docs/extensions-session.md`)
8. **subagent parity is closed at the contract layer, still implementation-backed later.** the contract says subagents need retained state, queueing, default presentation, and observe-only `subagent_*` / `job_*` publication over committed semantic state. (`docs/extensions-jobs-subagents.md:173-186,267-290,292-309`; `docs/extensions-events.md:93-143`)

## deliberate exclusions + open gaps

### deliberate exclusions

- raw custom component reach-through is excluded. zi does not expose pi-mono's `custom()` seam across the v2 public boundary. (`docs/extensions-ui-contract.md:90-90`; `.references/pi-mono/packages/coding-agent/src/core/extensions/types.ts:159-175`)
- raw editor component replacement is excluded. zi keeps editor actions and editor-modal flows, not `setEditorComponent()`-style ownership transfer. (`docs/extensions-ui-contract.md:85-86,91-91`; `.references/pi-mono/packages/coding-agent/src/core/extensions/types.ts:185-223`)
- raw terminal input listeners are excluded. terminal byte streams and focus routing stay host-private. (`docs/extensions-ui-contract.md:92-92`; `.references/pi-mono/packages/coding-agent/src/core/extensions/types.ts:121-123`)
- more generally, v2 excludes direct tui → lua reach-through and owner-boundary transport leakage as public api. (`docs/extensions.md:13-16`; `docs/runtime.md:16-19`)

### open gaps

- exact final public spellings for some v2 seams remain intentionally out of scope in the underlying contracts; this matrix only classifies capability, not binding syntax. (`docs/extensions-providers.md:124-133`; `docs/extensions-jobs-subagents.md:326-334`; `docs/extensions-events.md:281-289`)

## non-goals

this doc does not:

- define repo-consumer migration order or cutover sequencing. the root adr already says the cutover question is settled elsewhere. (`docs/adr/extensions-v2-cutover.md:71-77`)
- inventory current files, loaders, or transient implementation scaffolding. this is a parity statement over the v2 contract set. (`docs/extensions.md:26-28`; `docs/runtime-roots.md:206-224`)
- reopen exact lua api spellings, wire formats, or host-internal storage layouts that the individual contracts explicitly leave open. (`docs/extensions-events.md:281-289`; `docs/extensions-providers.md:124-133`; `docs/extensions-jobs-subagents.md:328-334`; `docs/extensions-commands-flags-actions.md:271-282`)
- claim bug-for-bug pi-mono equivalence. the target is pi-mono-level capability under zi's ownership model, not object-graph duplication. (`docs/extensions.md:18-28`; `docs/adr/extensions-v2-cutover.md:33-34,60-77`)
