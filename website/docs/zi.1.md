# zi(1)

## name

zi - yours-first coding agent

## synopsis

`zi [prompt]`

## pitch

There are many coding agents. This one is yours: ask zi to extend itself to best suit your workflow.

zi is a local-first coding agent harness with a Zig core, a terminal UI, durable sessions, and Lua extensions. Its job is not only to help with code, but to become the agent you want to use every day.

## what zi can do

- read, search, edit, and create files in your workspace
- run focused shell commands and project checks
- remember prior session context when asked
- load examples from `examples/` when writing extensions
- run Lua extensions that add tools, commands, UI, prompt customization, and workflow glue
- document durable contracts in `docs/` instead of hiding behavior in implementation details

## extension model

Extensions are small Lua programs loaded by zi. They let users shape zi without rebuilding the core.

Good extensions are small, explicit, and workflow-shaped. They should compose with the host and with other extensions instead of taking over the process.

See `docs/extensions.md` and `examples/extensions/` for the durable contract and copyable examples.

## website

The root site is generated by Zine. The online manual is generated from this page with `website/mdman`, a small Markdown-to-manpage and HTML tool adapted from rockorager/prise.

Build it with:

```sh
zig build web
```

The generated page lands at `zig-out/web/man/index.html`, ready to publish at `https://withzi.dev/man`.

## bugs

zi is young and intentionally smol. Prefer fixing unclear behavior at the boundary and documenting the contract here before adding more machinery.
